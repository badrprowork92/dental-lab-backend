# الأتمتة المحاسبية

يعتمد المشروع الحالي على **TiDB Serverless**. يدعم هذا المحرك بنية MySQL والجداول والعلاقات والحقول المولّدة، لكنه لا يدعم تنفيذ `CREATE TRIGGER` التقليدي. لذلك يطبّق التطبيق منطق المشغلات نفسه في طبقة الخادم عبر الدالتين `recalculateClientBalance` و`recalculateTechnicianBalance` بعد كل عملية مالية مُعرَّفة في التطبيق.

| الحدث | القاعدة المطبقة تلقائيًا |
|---|---|
| إنشاء طلب | رصيد العميل = مجموع إجمالي الطلبات − مجموع (المدفوعات + الخصومات) |
| إنشاء سند قبض | إعادة احتساب الرصيد بالمعادلة نفسها فور الحفظ |
| إسناد مرحلة لفني | رصيد الفني = العمولات المكتسبة − سندات الصرف |
| إنشاء سند صرف | إعادة احتساب رصيد الفني فور الحفظ |

يحافظ ملف `drizzle/0001_cheerful_jack_murdock.sql` على مخطط TiDB القابل للتشغيل. أما نص مشغل PostgreSQL الأصلي الوارد في ملف المواصفات فيبقى مرجعًا معماريًا للمستودع الذي يعتمد PostgreSQL/Supabase، بينما هذه الطبقة التطبيقية هي المكافئ التشغيلي المتاح في بيئة التطبيق الحالية.
